## 2. Step-by-Step Question Mapping (Q1 to Q14)

### Step 1: Subset Selection from the 2 Benchmarks
*The goal is to avoid random subsets and instead select a focused subset representing a concrete, motivated limitation of VGGT and/or D4RT.*

- **Question 1 (Flaw Identification & Justification):**
  - *Identified Flaw 1 (VGGT — Dynamic Motion Breakdown):* VGGT was trained almost exclusively on static multi-view scene reconstructions with a single anchor coordinate frame (camera 1). When encountering moving vehicles (DriveTrack) or dancing/gesturing humans (Panoptic Studio), VGGT interprets dynamic displacement as static depth or camera movement, causing severe 3D distortion.
  - *Identified Flaw 2 (D4RT — Sub-pixel 2D Drift & Long Occlusion):* D4RT evaluates queries independently without cross-query self-attention or multi-iteration correlation volumes (like CoTracker3 or TAPIR). Under long occlusions or low-contrast textures, D4RT's 9x9 patch embedding lacks sufficient discriminative power, causing sub-pixel drift.
  - *Subset Strategy:* Select 5–10 sequences from **TAPVid-3D (DriveTrack or Panoptic Studio)** and matching scenarios from **TAP-Vid (DAVIS / Kinetics)** featuring:
    1. Independent foreground object motion vs. static background.
    2. Temporary complete occlusion with re-emergence.
- **Question 2 (Qualitative & Quantitative Evidence):**
  - Show at least 3 qualitative examples illustrating this flaw (e.g. trajectory overlays on frames).
  - Quantify using benchmark metrics: show that on static background points, VGGT and D4RT achieve high $AJ$ / $3D\text{-}AJ$, but on dynamic moving foreground points, VGGT's $3D\text{-}AJ$ drops drastically.

### Step 2: 2D Point Tracking (TAP-Vid Subset)

- **Question 3 (Using VGGT & D4RT for 2D Tracking):**
  - **VGGT:** Run the built-in CoTracker2 tracking head over tracking features $T_i$ generated by the DPT layer. Query points are sampled from $T_{q}$ and matched across frames via cross-attention correlation.
  - **D4RT:**
    - *Method A:* Use the decoder's auxiliary 2D projection head $P_{2D} \in [0, 1]^2$.
    - *Method B:* Query 3D point $P(t_{tgt}, t_{cam}=t_{tgt}) = (X, Y, Z)$, recover intrinsics $f_x, f_y$, and project: $u = f_x \frac{X}{Z} + c_x, v = f_y \frac{Y}{Z} + c_y$.
- **Question 4 (Implementation of Mandatory Baselines):**
  1. *Pyramidal Lucas–Kanade (LK):* Multi-scale OpenCV `calcOpticalFlowPyrLK` chaining point displacements.
  2. *DINOv3 Feature-Similarity Matching:* Dense patch ViT features; match query patch feature using cosine similarity argmax.
  3. *DINOv3 Prototype-Based Matching:* Update reference feature online via running average: $p_t = \alpha p_{t-1} + (1-\alpha) f(\hat{x}_t)$.
  4. *LK + DINOv3:* Optical flow predicts coarse location; local window DINOv3 cosine similarity search refines it.
  5. *DINOv3 + Constant Velocity:* Estimate velocity $v_t = \hat{p}_{t-1} - \hat{p}_{t-2}$; predict $\tilde{p}_t = \hat{p}_{t-1} + v_t$; search DINOv3 within local neighborhood of $\tilde{p}_t$.
  6. *CoTracker3:* Run pretrained model on video tensor.
- **Question 5 (Qualitative Predictions):** Visual comparison of all 6 baselines + VGGT + D4RT on the same representative video clip.
- **Question 6 (Quantitative Benchmark Table):**
  Report Average Jaccard ($AJ$), Average Position Accuracy ($< \delta_{avg}$), and Occlusion Accuracy ($OA$) on the selected TAP-Vid subset.

### Step 3: 3D Point Tracking (TAPVid-3D Subset)

- **Question 7 (Adapting VGGT to 3D Tracking):**
  - Since VGGT natively outputs 2D tracks and static depth maps:
    1. Sample VGGT's predicted depth $D_t$ at predicted 2D position $\hat{y}_t$ to get $\hat{Z}_t$.
    2. Unproject using camera focal length $f_t$: $\hat{X}_t = \frac{(\hat{u}_t - c_x)\hat{Z}_t}{f_x}$, $\hat{Y}_t = \frac{(\hat{v}_t - c_y)\hat{Z}_t}{f_y}$.
    3. Transform to common world frame using VGGT's predicted extrinsics $(q_t, t_t)$.
    4. *Alternative:* Use external depth estimator (Depth Anything 3) to unproject VGGT's 2D tracks.
- **Question 8 (Implementation of Mandatory 3D Baselines):**
  - Combine 2D baselines (LK, DINOv3, DINOv3+CV, LK+DINO, CoTracker3) with estimated depth (e.g. Depth Anything 3) and unproject to 3D camera coordinates, followed by transformation to common reference frame using camera poses.
- **Question 9 (Qualitative 3D Trajectories):**
  - Show 3D trajectory plots (e.g. 3D scatter/line visualization or top-down X-Z bird's eye view) comparing baselines, VGGT adaptation, and native D4RT.
- **Question 10 (Quantitative 3D Table):**
  - Report $3D\text{-}AJ$, $APD_{3D}$ ($< \delta_{avg}^{3D}$), and $OA$ using Global Median Rescaling.

### Step 4: Extension (Lightweight & Colab-Compliant)

- **Question 11 (Problem Formulated):**
  - *Option 1 (Improving VGGT for 3D Tracking):* Address VGGT's static scene bias and depth scale inconsistency on moving objects.
  - *Option 2 (Improving D4RT for 2D Tracking):* Address D4RT's lack of fine-grained sub-pixel correlation matching in 2D.
- **Question 12 (Implementation Details & Training Recipe):**
  - *Efficiency Constraints:* Must run on Google Colab (single T4 / A100 GPU, 16 GB VRAM).
  - *Techniques:*
    1. **Feature Caching:** Pre-extract and cache VGGT / D4RT backbone embeddings $F$ to disk/RAM.
    2. **LoRA (Low-Rank Adaptation):** Freeze the backbone; attach LoRA rank-8/16 adapters to cross-attention / decoder projection heads.
    3. **AMP (Automatic Mixed Precision):** Train in `torch.cuda.amp.autocast(dtype=torch.float16)`.
- **Question 13 (Extended Metric Table):** Add the proposed extension rows to the benchmark table under identical evaluation conditions.
- **Question 14 (Results Discussion):** Analyze why the proposed extension achieved gains (e.g., reduced depth jitter, improved occlusion handling, sharper sub-pixel boundaries).
